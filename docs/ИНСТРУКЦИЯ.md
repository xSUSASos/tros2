# Тросовая система: запуск и настройка

Документ рассчитан на то, что вы читаете его подряд один раз, а потом
возвращаетесь к нужному разделу.

Порядок такой: сначала всё пробуется на модели без железа, потом
настраиваются приводы, снимается карта регистров, замеряется геометрия,
проводится калибровка — и только после этого система едет по координатам.
Перепрыгивать шаги не стоит: каждый следующий опирается на предыдущий.

---

## 1. Установка

Нужен Python 3.11 или новее. Проверить и доставить зависимости:

```bash
python -m pip install numpy scipy pyserial pydantic ruamel.yaml fastapi uvicorn pytest
```

Убедиться, что всё собрано правильно:

```bash
python -m pytest tests/ -q
```

Должно пройти без ошибок. Тесты гоняются целиком без железа — если они
падают, разбираться с гаражом ещё рано.

---

## 2. Быстрый старт на модели (железо не нужно)

```bash
python run.py --sim
```

Откройте `http://localhost:8000/`. Это полностью рабочая система: платформа
висит на четырёх упругих тросах, приводы отвечают с задержкой, момент
считается из настоящих натяжений. Здесь можно и нужно освоиться до того,
как что-то поедет в гараже.

Попробуйте по порядку:

1. **Разрешить приводы** — верхняя левая кнопка.
2. **Джог**: выберите шаг 200 мм и понажимайте стрелки. Платформа на поле
   поедет, тросы перестроятся.
3. **Ввод координат**: нажмите ⌂ — поля заполнятся центром поля и
   оптимальной высотой; нажмите «Ехать».
4. **Натяжение**: подвигайте ползунок и посмотрите на полоски тросов.
   Заметите, что поднять натяжение сразу во всех тросах не выходит —
   почему так, объяснено в разделе 6.4.
5. **G-code**: вкладка G-code, «Проверить», потом «Пуск».
6. **Аварийный стоп** — большая красная кнопка. Снимается повторным нажатием.

Также стоит прорепетировать утилиты, которые понадобятся в гараже:

```bash
python tools/bus_scan.py --sim
python tools/reg_probe.py --sim
```

## 3. Подготовка приводов

### 3.1 Настройки связи на панели каждого привода

Из коробки у всех приводов **адрес 1 и скорость 19200** — на такой шине
связи не будет вовсе, потому что четыре устройства с одинаковым адресом
отвечают одновременно. Поэтому на панели КАЖДОГО привода задайте:

| параметр | что задать | зачем |
|---|---|---|
| `P-181` | 1, 2, 3, 4 — разные | адрес на шине; −1 полностью выключает связь |
| `P-182` | `5` (115200 бод) | на 19200 цикл управления будет вчетверо медленнее |
| `P-183` | `1` (8E1) — оставить как есть | формат кадра |

После изменения параметров выполните сохранение `E-SEt` и перезапустите
привод по питанию, иначе настройки не вступят в силу.

### 3.2 Линия RS-485

Сейчас приводы соединены гирляндой, на конце переходник USB-RS485. Это
работает, но частота цикла управления упирается именно в шину.

**Если есть возможность — разбейте гирлянду на две шины по два привода и
поставьте второй переходник.** Частота цикла удвоится. Для обычного
движения это некритично, а вот для режима «вести за руку» разница между
приятным и вязким откликом.

Две шины описываются в конфиге так:

```yaml
buses:
  bus0: { port: "COM3", baudrate: 115200, parity: "E" }
  bus1: { port: "COM4", baudrate: 115200, parity: "E" }
```

и у якорей указывается, кто на какой шине:

```yaml
anchors:
  - {id: A1, pos: [...], bus: bus0, slave: 1}
  - {id: A2, pos: [...], bus: bus0, slave: 2}
  - {id: A3, pos: [...], bus: bus1, slave: 1}
  - {id: A4, pos: [...], bus: bus1, slave: 2}
```

Не забудьте согласующие резисторы на концах линии и общий провод — на 40
метрах рядом с силовыми кабелями приводов без этого будут сбои связи.
Панель показывает статистику линии, по ней сразу видно, здорова ли она.

### 3.3 Цепь разрешения SON — это ваш настоящий аварийный стоп

Разрешение привода у T3D приходит физическим входом DI, а не по Modbus.
Это к лучшему: **заведите вход SON всех четырёх приводов в одну цепь через
реле или кнопку-грибок**. Тогда размыкание цепи обесточивает приводы
независимо от того, жив ли компьютер, не завис ли Python и не отвалился ли
USB.

В конфиге укажите, кто управляет этой цепью:

```yaml
safety:
  enable_backend: manual     # щёлкает человек
  # enable_backend: gpio     # реле на ножке Raspberry Pi
  # enable_gpio_pin: 17
```

При `manual` панель честно пишет, что кнопка аварийного стопа в браузере
только обнулит скорости, а физически обесточить приводы не может.

### 3.4 Ограничение момента

При номинале мотора 4 Н·м и барабане ⌀60 мм полный момент даёт **132 Н** на
тросе. Этого достаточно, чтобы порвать слабое звено раньше, чем леску.
Программный предел натяжения — не защита, потому что он работает только
пока цел софт.

Поставьте ограничение момента в самих приводах. Номер параметра в
имеющемся мануале отсутствует; ищется тем же пробником (раздел 4) — в
профиле он назван `torque_limit_fwd` / `torque_limit_rev`. Пока он не
найден, панель показывает это как незакрытый риск.

## 4. Разведка: снятие карты регистров

В мануале есть номера параметров (`P-137` — уставка скорости, `P-181` —
адрес и так далее), но **нет таблицы соответствия этих номеров адресам
Modbus**: она поставлялась на диске. Без карты драйвер работать откажется —
и это правильно, гонять цикл управления по угаданным адресам опаснее, чем
не запуститься.

Карту не надо угадывать, её можно вывести. Найдите порт:

```bash
python tools/bus_scan.py --list-ports
python tools/bus_scan.py --port COM3
```

Сканер переберёт скорости, форматы и адреса и скажет, кто отозвался.
Дальше:

```bash
python tools/reg_probe.py --port COM3 --slave 1 --apply
```

Пробник делает четыре вещи:

1. **Находит базу параметров по подписи.** Раз обмен с приводом идёт,
   значит `P-181`, `P-182` и `P-183` в точности равны настройкам нашей
   стороны. Три известных числа подряд однозначно указывают смещение.
2. **Сверяет находку с паспортом двигателя** — обороты, ток, число пар
   полюсов должны совпасть с шильдиком `80AST-A1C04025Z1` (4.6 А, 3000 об/мин).
3. **Находит счётчик позиции и порядок слов.** Вас попросят провернуть
   барабан рукой на один и на два с половиной оборота: один оборот
   23-битного энкодера — это ровно 8 388 608 импульсов, и регистр, который
   изменился именно на столько, и есть искомый. Привод при этом должен быть
   ЗАПРЕЩЁН, иначе он будет сопротивляться.
4. **Проверяет, не пишется ли уставка скорости в EEPROM.** Это главный риск
   всего проекта: если пишется, то ресурс ячейки (порядка ста тысяч циклов)
   на частоте 50 Гц исчерпается примерно за **полчаса работы**, и привод
   выйдет из строя. Пробник сравнивает задержку записи с задержкой чтения и
   ищет диапазон-зеркало без EEPROM.

Ключ `--apply` записывает найденное в `config/drive_t3d.yaml`.

Если пробник скажет, что запись идёт в EEPROM и зеркала нет — **не
запускайте цикл управления**. Это придётся решать: искать недокументированный
регистр, переходить на импульсное управление или менять приводы.

## 5. Замер геометрии — от него зависит вся точность

Это самый важный ручной шаг, и его нельзя переложить на калибровку.

Проверка на модели показала: попытка вывести все двенадцать координат
якорей из одних лишь длин тросов плохо обусловлена. При шуме измерения в
1 мм ошибка положения выходит **40–70 мм**. Если же якоря замерены
дальномером с точностью 5 мм, ошибка позиционирования получается около
**10 мм**. Иначе говоря:

> **Ошибка позиционирования примерно вдвое больше ошибки замера якорей.
> Калибровка не может быть точнее вашей рулетки.**

Что мерить: **точку схода троса** — ролик или глазок, откуда трос уходит к
платформе, а не корпус лебёдки. Три координаты каждой из четырёх точек в
одной системе отсчёта. Лазерный дальномер даёт нужные 3–5 мм без труда.

Записать в `config/machine.yaml`:

```yaml
geometry:
  anchors:
    - {id: A1, pos: [    0.0,    0.0, 3000.0], bus: bus0, slave: 1}
    - {id: A2, pos: [ 6000.0,    0.0, 3000.0], bus: bus0, slave: 2}
    - {id: A3, pos: [ 6000.0, 5000.0, 3000.0], bus: bus0, slave: 3}
    - {id: A4, pos: [    0.0, 5000.0, 3000.0], bus: bus0, slave: 4}
```

Начало координат выбирайте удобное — например, первый якорь. Ось Z
направлена вверх, платформа висит НИЖЕ якорей.

## 6. Настройка конфигурации

Всё настраиваемое лежит в `config/machine.yaml`. Файл правится руками или из
вкладки «Настройки» в панели; при сохранении из панели комментарии в файле
остаются на месте.

### 6.1 Платформа

```yaml
platform:
  mass_kg: 5.0              # вместе с полезной нагрузкой
  landing_height_mm: 60.0   # высота центра платформы над полом при посадке
```

Массу стоит взвесить, а не оценить: от неё напрямую зависят и расчётные
натяжения, и граница рабочей зоны, и режим «вести за руку».

### 6.2 Лебёдки и намотка

```yaml
winch_defaults:
  drum_diameter_mm: 60.0
  drum_width_mm: 55.0
  line_diameter_mm: 0.50
  winding: multi_layer
  encoder_counts_per_rev: 8388608   # 23 бита, P-184 = 23
  max_rpm: 3000
  rated_torque_nm: 4.0
  direction: 1
```

Про `direction`: `+1` означает, что положительная уставка скорости
НАМАТЫВАЕТ трос. Проверяется в первом пуске (раздел 8); если трос
стравливается — поставьте `-1` для этой лебёдки.

Про намотку. При леске 0.5 мм и ширине барабана 55 мм в первом слое
помещается 110 витков, это **20.9 метра троса**. На раме 6×5 м самый
длинный трос около 8 м, то есть барабан не выходит за первый слой, и
намотка фактически однослойная. Но если леска толще (монофил на 50 кг —
это 0.8–1.0 мм), в слое поместится 10–13 м, и на длинных тросах пойдёт
второй слой. Разница масштаба между слоями:

```
слой 0 -> радиус 30.25 мм
слой 1 -> радиус 30.75 мм   (+1.65 %)
слой 3 -> радиус 31.75 мм   (+4.96 %)
```

Пять процентов на десяти метрах троса — это полметра ошибки, поэтому
**измерьте реальный диаметр лески штангенциркулем** и впишите точно.
Модель считает послойно и при однослойной намотке вырождается в линейную,
так что ошибиться в безопасную сторону нельзя.

### 6.3 Леска — главный ограничитель точности

При жёсткости около 4300 Н (плетёнка на 50 кг) пролёт 8 м под натяжением
100 Н удлиняется на **186 мм**. Монофил тянется в разы сильнее и для точной
работы непригоден в принципе.

Система это компенсирует: натяжение известно из момента мотора, а жёсткость
`ea_n` определяется калибровкой. Но выводы такие:

* берите **плетёнку**, не монофил;
* держите натяжение **низким и постоянным** — при постоянном натяжении
  вытяжка целиком уходит в калибровочное смещение и перестаёт мешать;
* не пропускайте калибровку с записью натяжений, иначе `ea_n` определить
  не из чего.

### 6.4 Натяжение — и почему общий уровень не регулируется

```yaml
tension:
  min_n: 8.0       # ниже — трос провисает и выпадает из модели
  target_n: 30.0   # цель для самого ненагруженного троса
  max_n: 120.0     # предел по САМОМУ СЛАБОМУ звену, не по разрывной лески
```

Посчитал нуль-пространство структурной матрицы: при четырёх тросах и трёх
координатах оно одномерно и равно **(1, −1, 1, −1)** — перетяжка
диагональных пар друг против друга. Вектор (1, 1, 1, 1) в него не входит.

> **Общий уровень натяжения не является свободным параметром: равновесие
> задаёт его однозначно. «Поднять натяжение сразу во всех тросах»
> алгоритмом нельзя.**

Поэтому ползунок «натяжение» управляет натяжением **самого ненагруженного
троса** — того, который рискует провиснуть. Это единственная физически
осмысленная цель при такой избыточности. Если попросить больше, чем даёт
геометрия, система так и скажет: «предел геометрии, а не настройки».

Поднять общий уровень можно только изменив условия: подвесить платформу
выше (у плоскости якорей натяжения резко растут), добавить веса, либо
поставить больше тросов — шесть тросов на три координаты дали бы три
свободных комбинации, среди которых есть и равномерная.

`max_n` ставьте по самому слабому звену цепочки: кронштейну, карабину,
точке крепления на платформе. Леска на 50 кг здесь обычно ни при чём.

### 6.5 Рабочая зона

```yaml
workspace:
  z_min_mm: 200.0
  z_max_mm: 2400.0
  inset_mm: 200.0
  feasibility_margin_n: 15.0
```

Задавать рабочую область одним отступом от стен неправильно. Карта запаса
горизонтального усилия для рамы 6×5 м с якорями на 3 м, платформой 5 кг и
пределами 8…120 Н, на высоте z = 1 м (в ньютонах):

```
 y=4.2   --    3    6    6    6    6    6    3   --
 y=2.5   --    3   19   36   43   36   19    3   --
 y=0.8   --    3    6    6    6    6    6    3   --
 x=     0.0  0.8  1.5  2.2  3.0  3.8  4.5  5.2  6.0   (метры)
```

В метре от стены запас уже 3 Н, хотя формально «отступ целый метр». Поэтому
граница **считается** из физики, а `inset_mm` добавляется сверху как
дополнительный запас. Панель рисует расчётную зону поверх поля.

`feasibility_margin_n` — сколько ньютонов возмущения платформа обязана
удержать, чтобы точка считалась рабочей. 15 Н разумный старт.

**Высота важнее отступов.** Внизу тросы почти вертикальны и горизонтального
усилия не создают, вверху упираются в предел натяжения:

```
z = 1000 мм  ->  запас в центре  43 Н, рабочей области 24 %
z = 2243 мм  ->  запас в центре 110 Н   (оптимум)
```

Кнопка ⌂ в панели показывает оптимальную высоту для вашей конфигурации.
Плоскость якорей недостижима принципиально: там все тросы горизонтальны и
вес держать нечем. Для рамы из примера предел около 2.6 м при якорях на 3 м.

### 6.6 Движение и контур управления

```yaml
motion:
  max_velocity_mms: 300.0
  max_acceleration_mms2: 500.0
  jog_feed_mms: 60.0
  homing_feed_mms: 30.0
  junction_deviation_mm: 1.0

control:
  loop_hz: 50
  position_kp: 1.5
  tension_kp: 0.30
  tension_deadband_n: 1.5
  watchdog_ms: 300
```

`loop_hz` не имеет смысла ставить выше того, что вытягивает шина. На одной
гирлянде из четырёх приводов реально 30–80 Гц; панель показывает
фактическую частоту, ориентируйтесь на неё.

`position_kp` увеличивайте, если платформа вяло догоняет цель, и уменьшайте
при раскачке. `tension_kp` — скорость подтяжки до целевого натяжения; ниже
`tension_deadband_n` натяжение не правится вовсе, чтобы приводы не дёргались.

### 6.7 Вести за руку

```yaml
admittance:
  gain_mms_per_n: 8.0
  deadband_n: 6.0
  max_velocity_mms: 150.0
```

`deadband_n` обязателен: момент измеряется грубо, в барабане и подшипниках
есть трение, и без мёртвой зоны платформа поползёт сама. Начните с 6 Н; если
дрейфует — увеличьте, если приходится давить слишком сильно — уменьшите.

Честное ограничение: тактильные стенды считают контур на килогерцах, здесь
частота упирается в Modbus. Ощущение будет мягким и слегка запаздывающим.
Две шины вместо одной заметно улучшают отклик.

## 7. Первый пуск на железе

Не спешите. Порядок проверок построен так, чтобы каждая следующая ошибка
обнаруживалась раньше, чем успеет навредить.

**Шаг 1. Связь без движения.**

```bash
python run.py
```

Если карта регистров не снята, программа откажется стартовать и скажет, что
делать. Это нормально, вернитесь к разделу 4.

Откройте панель. Приводы ещё не разрешены. Проверьте:

* в поле видны четыре троса и платформа;
* натяжения показывают осмысленные числа (хотя бы не нули на всех четырёх);
* частота цикла — 30 Гц и выше;
* в журнале нет потока ошибок связи.

**Шаг 2. Направление вращения — по одному мотору.**

Отцепите платформу или дайте тросам большую слабину. Разрешите приводы,
поставьте шаг джога 10 мм и сделайте один шаг. Смотрите на каждый барабан:
трос должен **наматываться** при команде в сторону этого якоря.

Если какая-то лебёдка крутится не туда — поменяйте `direction` на `-1` в
её записи в `winches` и перезапустите. Ошибка направления обнаруживается
именно здесь и стоит дёшево; в собранной системе она приводит к тому, что
контур управления разгоняет мотор до упора.

**Шаг 3. Выборка слабины.**

Прицепите платформу, положите её на пол под центром рамы. Нажмите
«Выбрать слабину». Тросы подтянутся до целевого натяжения по очереди, и на
полосках вы увидите, как растут показания. Если какой-то трос не тянется —
проверьте, не кончился ли он на барабане.

**Шаг 4. Первое движение.**

Малый джог, шаг 10 мм, по одной оси. Убедитесь, что платформа идёт туда,
куда просят, и что натяжения остаются в коридоре. Только потом увеличивайте
шаг.

Держите руку на аварийной цепи SON. Пока не пройдена калибровка, координаты
на экране — не настоящие, а от предположения о намотке.

## 8. Калибровка

Калибровка определяет то, что руками не измерить: сколько троса намотано на
барабане (то есть как отсчёт энкодера связан с длиной) и жёсткость лески.

**Что понадобится:** четыре–шесть точек на полу с известными координатами,
разнесённых по всей площади. Разметьте их рулеткой от того же начала
координат, что и якоря. Точность разметки прямо входит в результат, так что
не ленитесь.

**Процедура** (вкладка «Калибровка»):

1. Введите координаты первого репера. Z — высота центра платформы над полом
   в момент касания (обычно половина высоты платформы, параметр
   `landing_height_mm`).
2. «Опустить до касания». Платформа медленно пойдёт вниз. Касание
   определяется по **одновременному падению натяжения на всех четырёх
   тросах**: когда платформа встала на пол, вес принимает пол, и тросы
   разгружаются все сразу. Это гораздо более чёткий признак, чем скачок
   момента при боковом упоре, который легко спутать с рывком или трением.
3. «Записать точку».
4. Повторите для всех реперов.
5. «Рассчитать» — посмотрите на расхождение. Меньше 5 мм это хорошо,
   больше — проверяйте разметку реперов и не проскальзывает ли трос.
6. «Рассчитать и сохранить» — числа запишутся в `machine.yaml`.
   **Перезапустите сервер**, чтобы они применились.

**Что вы увидите в отчёте.** Скорее всего предупреждение о том, что задача
вырождена. Это ожидаемо и не страшно: если барабан не выходит за первый
слой, разделить «отсчёт при пустом барабане» и «длину при пустом барабане»
по этим данным нельзя — но их комбинация, которая и работает, определяется
точно. Проверка на синтетических данных: при шуме измерения 1 мм положение
восстанавливается с ошибкой **0.6–1.7 мм**.

**Как часто повторять.** Энкодеры абсолютные многооборотные с батарейкой,
поэтому позиция переживает выключение питания, и калибровка — операция «раз
на установку». Повторять нужно, если: сняли разъём энкодера или села
батарейка (привод покажет `Err40`), перематывали трос, меняли лебёдку или
двигали якоря.

## 9. Ежедневная работа

**Панель** — `http://localhost:8000/`.

| Что | Где |
|---|---|
| разрешить приводы | кнопка слева сверху |
| джог | крестовина, шаг выбирается кнопками ниже |
| поехать в координаты | блок «Ввод координат», ⌂ подставляет центр и лучшую высоту |
| натяжение | ползунок; полоски показывают каждый трос, синяя метка — цель |
| выбрать слабину | кнопка «Выбрать слабину» |
| вести за руку | кнопка «Вести за руку», выключается повторным нажатием |
| G-code | вкладка «G-code»: загрузка файла, «Проверить», «Пуск» |
| аварийный стоп | большая красная кнопка, снимается повторным нажатием |

**Про G-code.** Поддержаны `G0`, `G1`, `G2`, `G3`, `G4`, `G20`, `G21`,
`G28`, `G90`, `G91`, `G92`, `F`, `M0`, `M1`, `M2`, `M30`, `M112`. Дуги
разбиваются на хорды при разборе.

Непонятая строка — это **ошибка, а не пропуск**: программа с ошибками не
запустится, и вам покажут номер строки и её текст. На машине с четырьмя
тросами и киловаттными моторами «выполним что поняли» не годится.

Перед пуском программа проверяется целиком на попадание в рабочую зону —
до того, как платформа поедет.

Подача в G-code задаётся на минуту (`F3000` это 50 мм/с), и дополнительно
ограничивается тем, что вытягивают тросы: скорость барабана зависит от
направления движения, и в одном месте рабочей зоны та же подача требует
вдвое больших оборотов, чем в другом. Планировщик считает это для каждого
отрезка отдельно.

## 10. Перенос на Raspberry Pi 5

```bash
sudo apt install python3-pip
python3 -m pip install numpy scipy pyserial pydantic ruamel.yaml fastapi uvicorn
```

Скопируйте каталог проекта. Порт будет вида `/dev/ttyUSB0` — впишите его в
`buses`. Обязательно проверьте задержку переходника: у FTDI по умолчанию
`latency_timer` равен 16 мс, что в разы больше самого обмена и режет частоту
цикла. Система пытается выставить 1 мс сама, но если не вышло:

```bash
echo 1 | sudo tee /sys/bus/usb-serial/devices/ttyUSB0/latency_timer
```

Автозапуск через systemd, `/etc/systemd/system/cdpr.service`:

```ini
[Unit]
Description=Тросовая система
After=network.target

[Service]
Type=simple
User=pi
WorkingDirectory=/home/pi/cdpr
ExecStart=/usr/bin/python3 run.py --host 0.0.0.0
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now cdpr
```

Если разрешение приводов заведено на ножку Pi, поставьте в конфиге
`enable_backend: gpio` и номер ножки, и доставьте `gpiozero`.

## 11. Что делать, если

**Приводы не отвечают.** Проверьте по очереди: подана ли сила; не стоит ли
`P-181 = -1` (связь выключена); разные ли адреса у всех четырёх; совпадает
ли `P-182` с тем, что в конфиге; не перепутаны ли A и B на линии; есть ли
согласующие резисторы. Быстрее всего проверяется сканером:
`python tools/bus_scan.py --port COM3`.

**Программа отказывается запускаться и говорит про reg_probe.** Карта
регистров не снята — раздел 4. Это защита, а не поломка.

**Программа отказывается запускаться и говорит про EEPROM.** Пробник не
подтвердил, что уставку скорости можно писать часто. Пока это не решено,
запуск цикла выведет привод из строя за десятки минут. Обойти можно
`safety.require_eeprom_check: false`, но только осознанно.

**Частота цикла ниже 30 Гц.** Проверьте `latency_timer` переходника,
скорость линии (должна быть 115200), и число ошибок связи в панели. Самое
действенное — разбить гирлянду на две шины.

**В журнале «длины тросов не сходятся между собой».** Невязка прямой задачи
выросла. Обычные причины: трос проскользнул на барабане, где-то провис, или
калибровка перестала соответствовать реальности. Выше 100 мм движение
блокируется.

**Платформа дрожит на месте.** Уменьшите `position_kp`, увеличьте
`tension_deadband_n`. Если дрожание появилось только в режиме «за руку» —
увеличьте `deadband_n`.

**Не получается поднять натяжение до желаемого.** Это не настройка, а
геометрия — см. раздел 6.4. Система показывает достижимый максимум.

**Платформа не идёт в нужную точку, отказ «мало запаса».** Точка вне
рабочей зоны при текущей высоте и пределах натяжения. Попробуйте другую
высоту (кнопка ⌂ показывает оптимальную) или уменьшите
`feasibility_margin_n`, если понимаете, на что идёте.

**`Err40` на приводе.** Села батарейка абсолютного энкодера или снимался
разъём. Многооборотные данные потеряны, механический нуль надо сбросить, а
калибровку пройти заново.

## 12. Границы применимости

Что стоит знать заранее, чтобы не ждать от системы невозможного.

* **Точность ограничена замером якорей**, а не алгоритмом. При 5 мм на
  якорях ждите около 10 мм по положению.
* **Вытяжка лески — второй по величине источник ошибки.** Компенсируется по
  измеренному натяжению, но точность компенсации упирается в точность
  измерения момента приводом (единицы процентов).
* **Частота цикла ограничена шиной Modbus**, а не математикой: расчёт
  натяжений занимает 0.16 мс, то есть менее процента бюджета цикла.
* **Плоскость якорей недостижима**, рабочая зона заметно меньше рамы, и
  сильно зависит от высоты подвеса.
* **Общий уровень натяжения не регулируется** при четырёх тросах и трёх
  координатах.
* **Модель тросов — прямая линия.** Провис не моделируется; при лёгкой
  плетёнке и рабочих натяжениях это оправдано, но на очень длинных пролётах
  с малым натяжением появится дополнительная ошибка.
* **Поворот платформы не управляется.** Задано `dof: 3`, тросы считаются
  сходящимися в одну точку.

## 13. Где что лежит

```
run.py                  запуск сервера и панели
config/machine.yaml     геометрия, лебёдки, лимиты, натяжение, шины
config/drive_t3d.yaml   карта регистров привода (заполняет reg_probe)
tools/bus_scan.py       поиск приводов на линии
tools/reg_probe.py      снятие карты регистров и проверка EEPROM
cdpr/                   кинематика, натяжения, контур, режимы, G-code
drives/                 транспорт Modbus, драйвер T3D, симулятор
web/                    панель управления
docs/NOTES.md           инженерные заметки: что нашлось по ходу работы
tests/                  прогоняются без железа: python -m pytest tests/ -q
```

Поддержать другой привод — положить рядом ещё один YAML-профиль и указать
его при запуске (`--profile`). Поменять геометрию или число тросов — править
`machine.yaml`. Python при этом трогать не нужно.
