# Тросовая система перемещения (CDPR)

Четыре модуля с лебёдками прикручены к балкам по углам прямоугольника и лежат
в одной горизонтальной плоскости. Под ними на четырёх тросах висит коробка.
Управляются X и Y; высота задана один раз и командой не меняется.

Железо: сервоприводы HLTNC T3D с моторами 80AST-A1C04025, абсолютный
многооборотный энкодер, связь Modbus RTU по RS-485.

**Подробная инструкция — [docs/ИНСТРУКЦИЯ.md](docs/ИНСТРУКЦИЯ.md).**

## Запуск

Полностью рабочая система на модели, железо не нужно:

    python run.py --sim

Панель на <http://localhost:8000/>. Там настоящая физика: коробка висит на
упругих тросах, приводы отвечают с задержкой, момент считается из натяжений.

На железе:

    python tools/bus_scan.py --port COM5     кто на шине
    python tools/bus_probe.py --port COM5    сколько длится обмен
    python run.py

Тесты (228, все без железа):

    python -m pytest tests/ -q

## Как это устроено

Три слоя, каждый заменяется независимо:

    Transport   как байты ходят до устройства   drives/modbus_rtu.py, drives/sim.py
    Drive       что означают регистры привода   config/drive_t3d.yaml (данные, не код)
    DriveGroup  как опросить все оси за цикл    drives/base.py

Выше — контур управления с режимами. Режим отвечает на один вопрос: куда
система должна двигаться прямо сейчас. Как это исполнить — забота контура,
поэтому добавить режим значит написать один класс.

Всё настраиваемое живёт в YAML: `config/machine.yaml` — геометрия, лебёдки,
лимиты; `config/drive_t3d.yaml` — карта регистров. Поддержать другой привод —
положить рядом ещё один профиль, Python при этом не трогается.

## Что стоит знать до первого пуска

**Аварийный стоп — физическая кнопка, снимающая питание с приводов.** Софт ею
не управляет: кнопка в панели только обнуляет уставки. Энкодер абсолютный,
поэтому снятие питания привязку не теряет.

**Предел момента в самих приводах — единственная защита, не зависящая от
софта.** Мотор 4 Н·м на барабане ⌀60 даёт 133 Н на тросе; капрон ⌀0.3 мм
рвётся около 40–50. Отсюда 20 % в `safety.drive_torque_limit_percent`.

**Частоту цикла не назначают, её измеряют.** Двенадцать транзакций Modbus на
четыре оси — это десятки миллисекунд, и точность остановки равна скорости,
умноженной на период цикла. `tools/bus_probe.py` скажет и то, и другое.
Первый подозреваемый при плохих числах — latency timer USB-переходника: у
FTDI он по умолчанию 16 мс.

**Три числа надо померить, а не поверить им:** сколько импульсов в обороте
(проворот барабана рукой), сколько миллиметров троса в обороте (десять
оборотов и рулетка), какая жёсткость у лески (груз известного веса и
линейка). Ошибка в любом из них — ошибка масштаба во всём остальном.

**Общий уровень натяжения не регулируется.** При четырёх тросах и трёх
координатах равновесие задаёт его однозначно; свободна ровно одна комбинация —
перетяжка диагональных пар. Выбирается натяжение высотой рабочей плоскости:
чем больше провис, тем меньше натяжение.

**Реально управляема примерно треть площади рамы** — середина. У углов запас
усилия падает до нуля: три троса тянут прочь, и поперёк этого направления
держать нечем.

## Порядок первого запуска

1. Развести адреса приводов (`P-181` = 1..4) и скорость (`P-182` = 5).
2. `tools/bus_scan.py` — все четыре отзываются.
3. Проворот барабана рукой при снятом питании — импульсы на оборот.
4. Десять оборотов и рулетка — миллиметры на оборот.
5. `tools/bus_probe.py` — частота цикла.
6. Ручное вращение барабанов из панели, трос отцеплен — направления.
7. Выборка слабины, хоминг по углу, сохранение привязки.
8. Джог, координаты, G-code.

Первые шесть шагов ничего не двигают всерьёз и занимают полчаса. Они окупаются.
